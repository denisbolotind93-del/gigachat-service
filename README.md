# GigaChat Text Summarizer Service

Сервис на базе **FastAPI** и **GigaChat API** (Сбер) для краткого пересказа (суммаризации) русскоязычных и англоязычных текстов в 2–3 предложениях.

## Возможности и архитектура

- `api/` — HTTP-эндпоинты (`POST /process`, `GET /health`, `GET /health/ready`), валидация и нормализация входных данных через Pydantic.
- `services/` — бизнес-логика суммаризации, потокобезопасный `TTLCache` с составным ключом (SHA-256) и проверка качества ответов модели.
- `llm/` — клиент интеграции с GigaChat SDK с проверкой TLS-сертификатов, повторными попытками при сетевых сбоях и защитой от prompt injection.
- `config/` — управление конфигурацией (`pydantic-settings`) с разделением режимов `dev` / `prod` / `test` и структурированное JSON-логирование с корреляцией по `X-Request-ID`.

## Конфигурация и переменные окружения

Перед запуском создайте файл `.env` на основе `.env.example` и укажите действующие учётные данные GigaChat API (`GIGACHAT_CREDENTIALS`).

| Переменная | Обязательна | По умолчанию | Описание |
| :--- | :---: | :--- | :--- |
| `APP_ENV` | Нет | `dev` | Режим окружения (`dev`, `prod`, `test`). В `prod` отключаются полные стектрейсы в логах и устанавливается уровень `INFO`. |
| `GIGACHAT_CREDENTIALS` | **Да** | — | Ключ авторизации (Authorization Key) из личного кабинета Studio Сбер. Без него запуск невозможен. |
| `GIGACHAT_SCOPE` | Нет | `GIGACHAT_API_PERS` | Версия API (`GIGACHAT_API_PERS`, `GIGACHAT_API_B2B`, `GIGACHAT_API_CORP`). |
| `GIGACHAT_MODEL` | Нет | `GigaChat` | Название модели генерации. |
| `GIGACHAT_VERIFY_SSL_CERTS` | Нет | `true` | Проверка TLS-сертификатов сервера GigaChat. В продакшене должна быть включена (`true`). |
| `GIGACHAT_CA_BUNDLE_FILE` | Нет | `None` | Путь к файлу корневого сертификата НУЦ Минцифры РФ (`.pem`/`.cer`), если сертификат не установлен в системное хранилище. |
| `LLM_TIMEOUT` | Нет | `15.0` | Таймаут ожидания ответа от GigaChat в секундах (`> 0`). |
| `LLM_TEMPERATURE` | Нет | `0.3` | Температура генерации (`0.0` – `2.0`). |
| `LLM_MAX_RETRIES` | Нет | `2` | Количество повторных попыток при временных сетевых сбоях и ошибках `429`/`5xx`. |
| `LLM_RETRY_DELAY` | Нет | `0.5` | Базовая задержка между повторами в секундах. |
| `CACHE_TTL` | Нет | `300` | Время жизни записи в кеше в секундах (`> 0`). |
| `CACHE_MAXSIZE` | Нет | `200` | Максимальное количество записей в in-memory кеше (`> 0`). |

> **Важно про TLS-сертификаты:** GigaChat API использует сертификаты Национального удостоверяющего центра (НУЦ) Минцифры России. Для безопасной работы установите корневые сертификаты Минцифры в систему или укажите путь к файлу сертификата в `GIGACHAT_CA_BUNDLE_FILE`.

## Установка и запуск

### 1. Linux / macOS

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Отредактируйте .env и вставьте ваш GIGACHAT_CREDENTIALS
```

* **Режим разработки (с автоперезагрузкой кода):**
  ```bash
  uvicorn main:app --host 127.0.0.1 --port 8000 --reload
  ```
* **Промышленный (production) запуск (без `--reload`, несколько воркеров):**
  ```bash
  APP_ENV=prod uvicorn main:app --host 0.0.0.0 --port 8000 --workers 2
  ```

### 2. Windows (PowerShell)

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Откройте .env и вставьте ваш GIGACHAT_CREDENTIALS
```

* **Режим разработки:**
  ```powershell
  uvicorn main:app --host 127.0.0.1 --port 8000 --reload
  ```
* **Промышленный (production) запуск:**
  ```powershell
  \$env:APP_ENV="prod"; uvicorn main:app --host 0.0.0.0 --port 8000 --workers 2
  ```

Интерактивная документация Swagger UI доступна после запуска по адресу: `http://127.0.0`

## Спецификация API

### `POST /process` — Суммаризация текста

#### Параметры запроса (JSON)
- `text` (`string`, обязательное): исходный текст для пересказа.
  - **Ограничения длины:** от **15** до **5000** символов (проверяется после удаления лишних пробелов по краям и схлопывания повторяющихся пробелов). Строка из одних пробелов будет отклонена.

#### Поля ответа (JSON)
- `result` (`string`): итоговый краткий пересказ либо текст резервного сообщения при сбое внешнего API.
- `cached` (`boolean`): `true`, если ответ возвращён из локального TTL-кеша без повторного обращения к GigaChat.
- `fallback` (`boolean`): `true`, если при обращении к внешней модели произошёл временный сбой и сервис вернул резервное сообщение.

#### Семантика HTTP-статусов
- `200 OK` (`fallback: false`) — текст успешно обработан моделью или найден в кеше.
- `200 OK` (`fallback: true`) — внешний сервис GigaChat временно недоступен (таймаут, разрыв соединения, `5xx`/`429`). Согласно контракту API, сервис сохраняет работоспособность и возвращает резервное сообщение, **не сохраняя его в кеш**.
- `422 Unprocessable Entity` — нарушены правила валидации входных данных (пустая строка, текст короче 15 или длиннее 5000 символов, неверный тип поля).
- `503 Service Unavailable` — критическая ошибка конфигурации или авторизации в GigaChat API (`401`/`403`, неверный `GIGACHAT_CREDENTIALS`), требующая вмешательства администратора.

### Примеры запросов и ответов

#### 1. Успешный запрос (`200 OK`)

**Запрос:**
```bash
curl -X POST "http://127.0.0" \
  -H "Content-Type: application/json" \
  -d '{"text": "FastAPI — это современный высокопроизводительный веб-фреймворк для создания API на Python, основанный на стандартных аннотациях типов."}'
```

**Ответ:**
```json
{
  "result": "FastAPI представляет собой быстрый веб-фреймворк на Python для разработки API с использованием стандартных аннотаций типов.",
  "cached": false,
  "fallback": false
}
```

#### 2. Ошибка валидации (`422 Unprocessable Entity`)

**Запрос (строка из пробелов или слишком короткий текст):**
```json
{
  "text": "   Коротко   "
}
```

**Ответ:**
```json
{
  "detail": [
    {
      "type": "value_error",
      "loc": ["body", "text"],
      "msg": "Value error, Текст после удаления лишних пробелов должен содержать минимум 15 символов."
    }
  ]
}
```

#### 3. Резервный сценарий при временном сбое GigaChat (`200 OK`, `fallback: true`)

**Ответ:**
```json
{
  "result": "GigaChat временно недоступен. Попробуйте повторить запрос позже.",
  "cached": false,
  "fallback": true
}
```

### Healthcheck-эндпоинты

- `GET /health` — **Liveness-проверка**: возвращает `200 OK` (`{"status": "ok"}`), если процесс приложения запущен.
- `GET /health/ready` — **Readiness-проверка**: проверяет наличие корректных настроек и доступность GigaChat API. Возвращает `200 OK` (`{"status": "ready"}`) либо `503 Service Unavailable`.
